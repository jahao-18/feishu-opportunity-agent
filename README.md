# 商机录入与分析助手

一个面向公开体验的销售拜访分析 Agent。面试官通过网页输入拜访记录，系统按题目规则提取事实、判断 S0-S5 商机阶段、识别风险和未确认信息，并可将结果同步到飞书多维表格。

## 架构

```text
Streamlit public UI
        -> LangGraph controlled agent
        -> Pydantic validation + deterministic stage rules
        -> Feishu Bitable OpenAPI (optional)
```

Agent 采用受控状态图：输入检查 -> 事实提取 -> 事实边界校验 -> 阶段规则引擎 -> 风险与行动 -> 质量门禁 -> Controller 决策。大模型负责理解自然语言，代码负责业务规则、最终校验和副作用控制；飞书写入不在自动分析链路内。

## 已完成：阶段一

- CRM 字段使用 `EvidenceBackedFact` 表达，字段值与状态、原文证据不可分离。
- 支持 `confirmed`、`unconfirmed`、`contradictory`、`cannot_determine` 四种事实状态。
- 已确认事实必须有值和证据；未确认/无法判断字段禁止携带推测值；矛盾字段必须保留双方值和双方证据。
- `rules/stage_rules.json` 是可执行的 S0-S5 规则，S3 明确要求“需求仍有效”与“存在商务讨论”同时成立。
- `rules/analysis_rules.json` 版本化保存题库中的事实边界、推断、缺失、证据、矛盾和行动规则。

## 已完成：阶段二

- 火山方舟豆包通过 OpenAI 兼容客户端接入，默认使用 Function Calling 提交 `OpportunityFacts`。
- 模型只做有证据的事实提取，不输出或决定 S0-S5 商机阶段。
- Pydantic 校验失败、JSON 错误或模型请求失败时，最多显式重试两次。
- 重试 Prompt 会携带上一次校验错误，引导模型只修复结构和事实边界问题。
- 可切换 `json_object` 结构化模式，以兼容不支持强制工具调用的模型接入点。
- 每次调用记录模型、结构化模式、尝试次数、耗时和是否发生 Mock 降级。
- Mock 降级默认关闭；显式开启后，降级结果会被标记为必须人工复核。

## 已完成：阶段三

- 增加受控 `controller`，可选择请求补充、确认矛盾、等待保存确认、人工复核或结束。
- 每轮最多提出 1～2 个关键问题；推荐补充项不会阻塞保存，必填澄清项会阻塞保存。
- 增加多轮会话服务，保留请求编号、原始记录和历史回答，并在补充后重新提取事实与判级。
- 注册事实提取、规则读取、证据校验、客户历史、商机保存和跟进任务六类工具接口。
- 所有写入操作均与分析流程隔离；只有处于 `ready_to_save` 且用户明确确认后才能写飞书。
- 客户历史查询和飞书任务创建目前保留为显式不可用接口，将在后续飞书集成阶段实现，不会返回伪数据。

## 已完成：阶段四

- S0–S5 完全由版本化 JSON 规则和确定性代码判定，大模型无权直接指定阶段。
- 采用“满足规则的最高阶段”原则；未确认、无法判断或矛盾的信号均不能触发升级。
- 每次判级输出当前阶段、阶段名称、命中阶段、直接证据、下一阶段及其缺失条件。
- S3 必须同时具备有效需求/场景和明确商务讨论，“预算尚未确认”不会触发 S3。
- 多轮补充后若重算阶段低于历史阶段，会记录回退来源和原因，并由 Controller 转人工复核。
- 页面新增“下一阶段差距”，便于销售理解为什么未升级以及下一步应补什么证据。

## 已完成：阶段五

- 新增版本化的 `rules/risk_action_rules.json`，为 S0–S5 分别配置可执行的阶段推进动作。
- 确定性识别预算未确认、决策链不清晰、时间计划缺失、需求价值不足、客户态度模糊、商务条件冲突和前后信息矛盾。
- 风险等级会随阶段变化，例如 S3/S4 的预算缺失会提升为高风险。
- 每项风险强制携带字段状态或客户原文依据，无法生成无依据风险。
- 每项行动均包含优先级、具体动作、负责人、截止时间和推荐原因，并过滤“建议继续沟通”类泛化表达。
- 风险按等级和业务优先级排序，Controller 会优先追问最高风险所缺信息。
- 页面同时展示风险依据和行动原因，并显示风险规则版本。

## 本地运行

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
streamlit run app.py
```

默认 `MOCK_MODE=true`，不需要任何密钥即可运行三个演示样例。配置火山方舟后，将其改为 `false`。

## 火山方舟配置

在 `.env` 中填写：

```dotenv
MOCK_MODE=false
ARK_API_KEY=your-key
ARK_MODEL=your-endpoint-or-model-id
ARK_STRUCTURED_MODE=tool_call
ARK_TIMEOUT_SECONDS=30
ARK_MAX_RETRIES=2
ARK_FALLBACK_TO_MOCK=false
```

`ARK_MAX_RETRIES=2` 表示首次调用失败后最多再尝试两次，总尝试次数不超过三次。优先使用 `tool_call`；若目标接入点不支持强制工具调用，可改为 `json_object`。

## 飞书多维表格配置

1. 在飞书开放平台创建企业自建应用。
2. 开通多维表格记录读写权限，并发布应用版本。
3. 将应用添加为目标多维表格的协作者。
4. 在 `.env` 中填写应用凭据、Base app token 和 table id。
5. 设置 `FEISHU_SYNC_ENABLED=true`。分析完成后仍需在页面点击“确认保存到飞书多维表格”。

可以执行以下命令检查连接和表字段：

```powershell
.\.venv\Scripts\python.exe scripts\check_feishu.py
```

密钥只能放在部署平台的 Secrets/环境变量中，不能提交到 Git。

## 当前 MVP 边界

- 支持文本拜访记录。
- Mock 模式用于无密钥开发和演示兜底。
- 阶段判断严格采用 `rules/stage_rules.json`，不由模型自由决定。
- 飞书字段名称需要在正式接入时与目标数据表列名做一次映射校对。
- 客户历史读取已接入；P0 跟进任务由飞书工作流创建。

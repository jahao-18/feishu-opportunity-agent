# 飞书开放平台与多维表格接入

## 1. 创建并授权企业自建应用

1. 在飞书开放平台创建企业自建应用。
2. 为应用开通多维表格读取和写入所需权限，并在权限页面确认字段列表、记录查询、新增记录和更新记录 API 均已授权。
3. 创建并发布应用版本，在当前企业内安装应用。
4. 在目标多维表格的协作者设置中添加该应用，授予可编辑权限。

应用权限和多维表格协作者权限缺一不可。权限调整后需要重新发布应用版本。

## 2. 配置环境变量

在项目根目录 `.env` 中填写：

```dotenv
FEISHU_SYNC_ENABLED=true
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_BITABLE_APP_TOKEN=xxx
FEISHU_BITABLE_TABLE_ID=tblxxx
FEISHU_STAGE_RULES_TABLE_ID=
FEISHU_TIMEOUT_SECONDS=20
FEISHU_MAX_RETRIES=2
```

- `App Token` 位于多维表格链接的 `/base/` 后面。
- `Table ID` 位于链接查询参数 `table=` 后面。
- `FEISHU_STAGE_RULES_TABLE_ID` 可选。不配置时使用项目内的 `rules/stage_rules.json`。
- 不要把真实密钥写进 `.env.example`、Git 或网页前端。

## 3. 商机分析表字段

当前项目已兼容题目模板中的既有字段名，无需重命名或删除原字段：

| Agent 语义字段 | 当前多维表格字段 |
|---|---|
| 原始拜访记录 | 拜访原文 |
| 预算 | 预算信息 |
| 商机阶段 | AI 建议阶段 |
| AI置信度 | AI 置信度 |
| 处理状态 | 人工确认状态 |
| 规则版本与风险规则版本 | 分析版本 |

由于现有“商机编号”是自动编号，项目额外建立了文本字段“请求编号”，专门用于幂等写入。不要用自动编号字段替代它。

新建空表时，也可以使用下面这套标准字段名：

| 字段 | 推荐类型 |
|---|---|
| 请求编号 | 文本（主字段） |
| 原始拜访记录 | 多行文本 |
| 客户名称 | 文本 |
| 客户需求 | 多行文本 |
| 核心场景 | 多行文本 |
| 预算 | 文本 |
| 决策人 | 多行文本 |
| 影响人 | 多行文本 |
| 时间计划 | 文本 |
| 商机阶段 | 单选或文本 |
| 阶段判断依据 | 多行文本 |
| 风险 | 多行文本 |
| 下一步行动 | 多行文本 |
| 未确认信息 | 多行文本 |
| 矛盾信息 | 多行文本 |
| AI置信度 | 数字 |
| 处理状态 | 单选或文本 |
| 规则版本 | 文本 |
| 风险规则版本 | 文本（也可合并写入规则版本） |

程序启动时会自动读取字段并报告缺失项。保存前还会再次检查，避免因表结构错误产生半成品记录。

## 4. 可选的阶段规则表

若要让销售运营在飞书中维护 S0–S5 规则，创建另一张表并配置 `FEISHU_STAGE_RULES_TABLE_ID`。程序支持两种结构：完整结构如下，或题目模板已有的简化结构“阶段 / 名称 / 达成条件 / 优先级”。简化结构会按 S0–S5 自动关联到内置的证据信号，不让自然语言条件直接决定程序逻辑。

| 字段 | 类型 | 示例 |
|---|---|---|
| 阶段代码 | 文本 | S3 |
| 阶段名称 | 文本 | 商务评估 |
| 排序 | 数字 | 3 |
| 条件 | 文本 | 已讨论商务条件，且需求仍有效 |
| 规则JSON | 多行文本 | `[{"any_of":["customer_needs","core_scenarios"]},{"any_of":["commercial_discussions"]}]` |
| 是否兜底 | 复选框 | 仅 S0 勾选 |
| 启用 | 复选框 | 勾选 |

必须恰好有六条启用规则，覆盖 S0–S5，且只有 S0 为兜底。读取或校验失败时，Agent 会使用本地规则并在页面显示警告，不中断分析。

## 5. 连接检查

```powershell
.\.venv\Scripts\python.exe scripts\check_feishu.py
```

检查脚本输出启用状态、配置状态、当前字段和缺失字段，不输出 App Secret 或访问令牌。

真实写入联调可运行：

```powershell
.\.venv\Scripts\python.exe scripts\smoke_feishu_write.py
```

脚本使用固定请求编号 `FDE-STAGE6-SMOKE-001`，重复运行会更新同一条联调记录，不会不断新增。

## 6. 写入行为

- 分析过程不会自动产生外部写入。
- 用户点击“确认保存到飞书多维表格”后才会保存。
- 程序按“请求编号”先查询已有记录：存在则更新，不存在则新增，避免重试产生重复数据。
- 写入失败不会清空当前分析；修正配置后可再次点击保存。

# 阶段七：飞书工作流与业务协同

## 目标

公开网页中的自建 Agent 负责理解拜访记录、执行确定性规则并写入多维表格；飞书工作流负责组织内协同。两者通过“商机分析表新增记录”解耦，飞书工作流失败不会阻塞网页分析。

## 已配置工作流

- 触发器：`商机分析表`新增记录，且`请求编号`非空。
- 分支模式：同时执行所有满足条件的分支，而不是只命中第一条。
- 通知接收人：当前演示账号（正式部署时替换为销售负责人字段或销售群）。

| 分支 | 飞书条件 | 动作 |
| --- | --- | --- |
| 重点商机 | `AI 建议阶段`为 S3、S4 或 S5 | 发送重点商机提醒，并附“查看商机”按钮 |
| 高风险 | `风险`包含`[高]` | 发送人工复核提醒，并附“查看商机”按钮 |
| P0 跟进 | `下一步行动`包含`[P0]` | 创建“【P0】商机关键跟进”飞书任务 |
| 信息待补充 | `未确认信息`不等于`无` | 发送补充信息提醒，并附“查看商机”按钮 |
| 人工复核 | `人工确认状态`等于`需修改` | 发送异常复核提醒，并附“查看商机”按钮 |

Agent 写入空列表时使用明确哨兵值`无`，避免工作流把空值误判为“存在未确认信息”。

## 代码侧镜像规则

`agent/collaboration.py`用纯函数镜像上述五条路由，用于单元测试、演示讲解和后续迁移。它不会直接发送消息，副作用仍由飞书工作流统一执行。

## 安全边界

- 网页分析过程不会自动写飞书；用户确认保存后才执行幂等 Upsert。
- 只有“新增记录”触发协同；同一请求编号的重试更新原记录，不会重复创建任务或重复通知。
- 飞书应用密钥只保存在环境变量中。
- 当前接收人是演示账号；切换到真实客户环境前应改为动态销售负责人或指定群。

## 验证步骤

1. 在工作流页面确认五个分支均无“未完成设置”。
2. 保存并启用工作流。
3. 从网页生成一个同时满足 S3+、高风险、P0、信息不足和人工复核条件的新请求并保存。
4. 在工作流“运行日志”中确认五条分支均执行。
5. 在飞书消息和任务中心确认通知、任务及记录跳转链接。

> 注意：工作流只在新增记录时触发。验证时必须使用新的`请求编号`。
